# PBS2D × _InventoryPlug — Система магазинов (Tarkov-style)

> Решение зафиксировано перед реализацией. Расширяет интеграцию из
> [PBS2D-Integration-Decisions.md](PBS2D-Integration-Decisions.md).
> Принцип тот же — **Вариант A**: адаптер поверх, без правок кода PBS_2D и UPM-пакета
> (где возможно; один аккуратный хук в PBS обсуждается в §6).

## 0. TL;DR
Магазин — **отдельный предмет инвентаря**, который держит патроны в своём
`ItemInstance.nestedContainer`. Россыпь патронов сама **не стреляет** — только
**набивает** магазины (медленно, 1 патрон за ~0.5с, скорость настраивается).
Оружие **без вставленного непустого магазина не стреляет**. Боевая перезарядка (R) —
**смена магазина**: берётся самый полный совместимый магазин из инвентаря.

## 1. Принятые решения

| Вопрос | Решение |
|---|---|
| Охват | **Полный Tarkov** — магазин = отдельный предмет; россыпь не стреляет; без магазина не стреляет |
| Набивка магазина | **И контекстное меню инвентаря, И зажатая клавиша в игре** (оба способа) |
| Боевая перезарядка R | **Смена магазина** — свап самого полного совместимого; пустой/недобитый возвращается в инвентарь |
| Старт | Оружие в руки попадает **с уже снаряжённым магазином** |
| Скорость набивки | Настраиваемая, дефолт **0.5 с/патрон** |

## 2. Модель данных

### 2.1. Магазин-предмет
`ItemDefinition` (например `Mag_AK_30.asset`):
- `itemType = Generic` (или новый тип, см. §7-future), `isContainer = true`;
- габарит в сетке как у таркоского магазина (занимает место);
- `nestedContainer` хранит **один стак патронов** (`stackCount` = заряжено).
  Ёмкость (30) ограничивает игровой загрузчик, **не** `ammo.maxStack`.

### 2.2. MagazineCatalog (новый game-side ScriptableObject)
Привязывает мета-данные магазина **без правок `ItemDefinition` пакета** — тот же приём,
что `InventoryWeaponBinding` для оружия. Список записей:

| Поле | Смысл |
|---|---|
| `magazineDefinition` | ItemDefinition магазина |
| `caliber` | ItemDefinition патрона (калибр) |
| `capacity` | ёмкость, напр. 30 (AK), 17 (Glock) |
| `loadSecondsPerRound` | скорость набивки, дефолт 0.5 |

Оружие уже знает свой калибр через `InventoryWeaponBinding.ammoDefinition` —
магазин совместим с оружием, если их `caliber` совпадает.

### 2.3. Где живёт «вставленный магазин»
Магазин, вставленный в активное оружие, — это `ItemInstance` в инвентаре,
помеченный мостом как «вставленный в оружие X». Хранит заряд в `nestedContainer`,
поэтому переживает переключение слотов хотбара и сейв/лоад пакета.

## 3. Поток: набивка магазина (медленно)
Корутина `LoadMagazineRoutine(mag, ammoSource, perRound)`:
1. каждые `perRound` секунд: если магазин не полон и в источнике есть патрон —
   перенести 1 патрон (`ammoSource.stackCount--`, заряд магазина `++`);
2. играть звук «вставить патрон», обновить счётчик `X/ёмкость` в UI;
3. стоп при: магазин полон / источник пуст / прерывание.

Запуск двумя способами (оба включены):
- **Контекстное меню инвентаря**: ПКМ по магазину/пачке → «Снаряжать».
- **Зажатая клавиша в игре**: держим клавишу — активный магазин набивается из россыпи в инвентаре.

## 4. Поток: стрельба
- Мост ставит `Gun.CurrentLoadedAmmo` = заряд вставленного магазина (0, если магазина нет).
- `Gun.CanShoot()` уже требует `CurrentLoadedAmmo > 0` ⇒ **без магазина/пустой → не стреляет (само)**.
- На выстреле `Gun` декрементит `CurrentLoadedAmmo`; мост ловит это (как сейчас с резервом)
  и списывает 1 патрон из `nestedContainer` вставленного магазина.

## 5. Поток: боевая перезарядка (R = смена магазина)
1. Найти в инвентаре **самый полный совместимый** магазин (калибр оружия).
2. Если найден — извлечь текущий магазин (вернуть в инвентарь как предмет с его остатком),
   вставить новый; `CurrentLoadedAmmo` = заряд нового.
3. Анимацию можно переиспользовать из `Reload.ReloadMagazine` (визуал), но числа патронов
   ведёт мост, а не штатный reserve-путь.
4. Нет совместимого магазина → перезарядка не происходит (щелчок/нет действия).

## 6. Технический нюанс: штатный `Gun.ReloadGun()`
Штатный путь тянет патроны из `CurrentReserveAmmo` (старая модель «россыпь = резерв») и
переливает в `CurrentLoadedAmmo` через `Reload.HandSnap`. В новой модели его надо
**нейтрализовать/перехватить**, иначе он продублирует логику. Варианты:
- **(A) Без правок PBS** — мост держит `CurrentReserveAmmo = 0`, а R перехватывает на своей
  стороне (свап магазина); штатный `ReloadGun` при reserve=0 ничего не делает.
- **(B) Малый хук в PBS** — флаг «внешнее управление боезапасом» в `Gun`, отключающий
  внутренний reserve-путь. Чище, но трогает PBS.

Дефолт — **(A)**, без правок PBS. Если упрёмся в анимацию/тайминги — обсудим (B).

## 7. План работ
1. `MagazineCatalog` SO + ассеты магазинов (`Mag_AK_30`, `Mag_Glock_17`) + иконки/габариты.
2. Расширить мост: вставленный магазин, синк `CurrentLoadedAmmo`↔заряд, `CurrentReserveAmmo=0`.
3. `LoadMagazineRoutine` + два триггера (контекстное меню инвентаря, зажатая клавиша).
4. Перехват R → свап магазина (самый полный совместимый).
5. HUD: `заряд_магазина / ёмкость`, прогресс набивки.
6. Пилот на GunRangeTest: AK с `Mag_AK_30`, Glock с `Mag_Glock_17`, оба со снаряжённым
   магазином на старте; в луте — пачки патронов + пустые/полные магазины.

## 8. Будущее (вне текущего объёма)
- Отдельный `ItemType.Magazine` + слот-разгрузка под магазины (Tarkov rig).
- Разные типы патронов в одном калибре (бронебойные/обычные) — стак калибра как смесь.
- Проверка магазина (Check ammo) — показать примерный заряд без точного числа.
- Сейв/лоад заряда магазинов (опирается на сериализацию `nestedContainer` пакета).

## 9. Статус реализации (пилот — GunRangeTest)

**Готово и проверено** (детерминированные тесты в play mode + end-to-end на реальном спавне):

| Поведение | Статус |
|---|---|
| Старт оружия со снаряжённым магазином (AK 30 / Glock 17) | ✅ |
| Россыпь патронов НЕ резерв (`Gun.CurrentReserveAmmo` держится в 0) | ✅ |
| Выстрел списывает патрон из вставленного магазина | ✅ |
| Пустой магазин → не стреляет, авто-долива из россыпи нет | ✅ |
| Набивка магазина из россыпи (1 патрон / `loadSecondsPerRound`) | ✅ |
| R = смена магазина (самый полный совместимый; старый → в инвентарь) | ✅ |

### Управление (пилот)
- **F** — подобрать предмет (инвентарный `HoverPickup2D`, Mouse-режим).
- **2** — взять AK в руки (PrimaryWeapon-слот хотбара); **1/H** — пустые руки.
- **R** — боевая перезарядка = смена магазина на самый полный совместимый.
- **T** — зажать: набивать активный магазин из россыпи (по 1 патрону за 0.5с).
- **ПКМ по магазину в инвентаре → «Снаряжать»** — то же, через контекстное меню.
- **G** — выбросить активный предмет хотбара.

### Созданные ассеты
- `Items2D/Mag_AK_30.asset`, `Items2D/Mag_Glock_17.asset` — магазины (контейнеры 1×1, габарит 1×2).
- `Inventory/MagazineCatalog_PBS2D.asset` — каталог (AK→7.62×39/30, Glock→9×19/17, 0.5с/патрон).
- Каталог привязан к `PBS2D_InventoryBridge.magazineCatalog` на `Player.prefab`.
- `MagazinePilotKit` на `InventoryRig` в GunRangeTest: авто-надевает рюкзак (BackPack2D, 4×6),
  сеет 2 магазина АК (полный + пустой), 1 Glock (17) и россыпь 60×7.62 + 40×9×19.

### Код
- `Scripts/Integration/PBS2D/MagazineCatalog.cs` — каталог (SO).
- `Scripts/Integration/PBS2D/PBS2D_InventoryBridge.cs` — магазинная логика (свап/набивка/синк/детект выстрела).
- `Scripts/Integration/PBS2D/MagazinePilotKit.cs` — стартовый кит (сценарное удобство).

### Известные ограничения / доработки (не критично)
- **HUD-резерв = «/0».** Штатный `WeaponUI` показывает `loaded / reserve`, а резерв держим в 0
  (россыпь не стреляет). Запасные магазины в HUD не отражены. Полировка: завести
  собственный read-out (магазины/россыпь) в `WeaponHotbarUI`.
- **Иконка магазина — плейсхолдер** (иконка патрона): текстура `Icon_Magazine.png` импортирована
  как Default (не Sprite). Чтобы не трогать ассет PBS — поставить отдельный спрайт магазина.
- **Анимация перезарядки.** Свап мгновенный (числа корректны). Можно переиспользовать визуал
  `Reload.ReloadMagazine` без переноса патронов.
- **Магазин уходит вместе с оружием при дропе (G).** Повторное взятие даёт новый полный
  стартовый магазин (следствие `startWithLoadedMag`). Для хардкора — выключить флаг.
- **Дроп магазина в мир** (когда инвентарь полон при свапе) использует fallback `WorldItem2D`
  (габарит 1×2 → лёгкое искажение). Низкий приоритет; при необходимости задать `worldPrefab2D`.
